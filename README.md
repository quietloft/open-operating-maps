# Open Operating Maps

**Business operations, mapped — open, editable, forkable.**

Every business runs on the same handful of systems. Most companies keep them
scattered across a Google Doc, a task board, a drive, and someone's head.
This repository maps them **as plain text**, so that anyone can read, fork,
adapt and improve them — with no subscription, no proprietary file format and
no vendor in the middle.

> Derived from no one's product. Built from what operations actually are.
> Licensed CC BY 4.0: use it, change it, credit the project.

## Why plain text

| Proprietary map | This repository |
| --- | --- |
| One vendor's Figma board | Markdown + Mermaid, renders on GitHub |
| Cannot be diffed or reviewed | Pull requests, version history, forks |
| Locked behind a price | Free, forever |
| One author's opinion | Anyone can improve it |

## How to use it

1. Pick the department you want to fix first — usually the one that hurts most.
2. Read its map (`maps/<department>/README.md`): it lists the **eight areas** that
   department is actually made of.
3. For each area open the file and work through it: **objective → process →
   tools → owner → KPIs → failure modes → checklist**.
4. Copy what you need into your own workspace. Nothing here needs to be installed.

## The eight areas, for any department

Every department map follows the same skeleton, because a system is only usable
when it has the same shape everywhere:

1. **Objective** — one sentence, measurable.
2. **Inputs** — what must exist before the process can start.
3. **Process** — numbered steps, no adjectives, executable by a new hire.
4. **Tools** — where the work actually lives (one primary tool, not five).
5. **Owner** — a role, never "everyone".
6. **KPIs** — two or three, leading indicators preferred.
7. **Failure modes** — how this area breaks in real companies.
8. **Checklist** — the ten-minute weekly review.
